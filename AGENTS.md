# Repository Guidelines

Terminal (CLI) Mario-style platformer in Go — plus a browser WASM build — with an online high-score board on Supabase. Single module `github.com/Daviey/mario`, stdlib-only, no external dependencies. Public repo: `github.com/Daviey/mario`. MIT-licensed.

## Project Overview

A fully playable SMB-style platformer rendered as half-block terminal pixels (native) or canvas pixels (browser). The engine is **fully deterministic** — no randomness, no wall-clock in simulation — so identical input sequences reproduce identical games (the tests rely on this). Scores submit to a Supabase PostgREST table carrying the run's input recording; a GitHub Action verifier replays each recording and keeps only rows that reproduce their claimed score (legacy pre-replay rows stay unmarked).

## Architecture & Data Flow

```text
stdin bytes ──▶ Router.Feed() ──┬─(UI active)──▶ Router.plain ──▶ UI.keys (internal/ui/ui.go)
                               ├─(title 'l')──▶ io.plain ──▶ scoreUI.note
                               └─(playing)───▶ input.Mapper.Feed
                                                │ Poll() each tick
60 Hz ticker ─▶ play() (main.go) ─▶ engine.Game.Update(engine.Input)
                                    │
                     render.Stream.Draw(g, ui) ─▶ worldFrame → Frame (square pixels)
                     native: Diff → ANSI half-blocks/spaces to stdout (differential SGR, see Gotchas)
                     wasm:   RenderPixels → RGB bytes → page's marioFrame()
                    efi:    RenderPixels → RGB bytes → scaled fbdev blit (/dev/fb0)
```

 - **Spine**: the importable root package `mario` (library facade, `mario.go`) owns the 60 Hz loop: `App.Run(*render.Stream)` blocks for the native terminal; `App.Step()` drives one tick for clock-owning consumers (the browser build). Both entries are thin: `cmd/mario` (native CLI) and `cmd/web` (WASM).
- **EFI-stub bootable**: A single-file UEFI boot image (`dist/mario.efi`) compiled via `make efi` that boots straight into the game with no OS. The image embeds a tiny custom Linux kernel (EFISTUB, simpledrm/vesafb, evdev) and an initramfs containing only the static `cmd/efi` binary as `/init`. It drives `App.Step()` at 60 Hz, reads keyboards via evdev, and blits `RenderPixels` directly to `/dev/fb0`. The leaderboard is offline.
- **Input routing rule**: while any leaderboard screen holds the keyboard (`scoreUI.capturing()`), raw bytes are decoded via `input.PlainDecoder` and passed to the UI. The mapper speaks `CSI u` natively, but the UI is strictly byte-oriented (`internal/ui/router.go`).
- **Engine** (`engine/`): `Game.Update(Input)` advances one tick through states `StateTitle → StateWorldCard → StatePlaying → StatePipeIn → StatePipeOut → (flag) StateFlagSlide | (axe) StateBridgeFall → StateWalkCastle → StateScoreTick → StateWorldCard(next) … StateGameOver/StateWin` (world card skippable with AnyKey; death adds a 30-tick freeze-frame then respawns at `Level.CheckpointX` when reached). Shared body/vec types in `entity.go`; physics in `physics.go`; levels are ASCII grids parsed by `ParseLevel`, built-ins in `levels.go` (seven levels: 1-1, underground 1-2, 1-3, 2-1, underground 2-2, sky 2-3, castle 2-4; plus 1-1's flagless underground cellar room entered via `Warp`). 2-4 ends with the Bowser boss (`engine/bowser.go`): he hops and breathes fire (pure-hash mood, no RNG) on a bridge of `TileBridge` planks ('b') over lava; five player fireballs, star contact or the axe ('x', `Level.AxeX/AxeY`) kill him — touching the axe sweeps the bridge left-to-right and drops him into the lava (`StateBridgeFall` → auto-walk). Castle levels have NO flagpole: `Level.GoalX()` (flag else axe) is the goal abstraction `updateWalkCastle`'s door, `render.castleRect` and `flagReachable` all consume, and `TestDefaultLevelsValid`'s goal window checks it too. Power states are `PowerSmall/PowerSuper/PowerFire` plus star power (`Player.Star` ticks: kill-on-touch, absorbs all damage except lava/pits, palette flicker). Fireballs (max 2, Run-key rising edge), piranha plants (rise/sink cycle + mercy rule while the player stands near), paratroopas (`KindPara`: hop while walking; a stomp demotes them to walking koopas), fire bars (`FireBar`: angle is a pure function of the tick; level char 'h'), lava ('L': non-solid, kills on touch), hidden blocks ('H' coin / '1' 1-UP: invisible, non-solid, trigger only on a rising head-bump via `bumpHidden`), the stomp/shell combo ladder (`stompLadder`, 1-UP past the end; Bowser is the one enemy that can never be stomped), HURRY at `Time ≤ 100`, and sound events (`Game.Events`, drained each tick by the host; the wasm build forwards them to the page's `marioSfx` — boss events `axe`/`bowser`/`bowserdie` are synthesized in `web/boot.js` and bell-forced in `cmd/mario/bell.go`).
- **Themes**: `Level.Theme` (`ThemeOverworld`/`ThemeUnderground`/`ThemeSky`/`ThemeCastle`) re-skins the palette in `render.paletteFor` — underground = black sky, blue bricks, brick ceiling; sky = pale sky, sandstone terrain, clouds only; castle = black sky, grey stone, no sky dressing.
- **Replay verification** (`replay/`): `App.Step` records every run tick (`replay.Recorder`, RLE `{"v":1,"ticks":N,"runs":[[mask,count],...]}` wire format, 130k-tick cap); `replay.Run(levels, mode, json)` re-executes a stream and returns score/level/state. `replay.Run` starts classic runs from `Game.Reset()` and daily runs from `Game.BeginDaily()` — the recording's first tick is the first world-card tick (the title-dismiss tick is excluded; a card reached from `Dying`/`ScoreTick` continues the same recording, any other card entry starts a fresh one).
- **Leaderboard** (`internal/ui`, `board/`, `replay/`): `ui.UI` state machine (`UIOff/UIAsk/UIEntry/UIBoard`) driven by `Tick(g)`; network runs off the tick loop via injectable `submit`/`fetch` funcs (nil → real `board.Client` from env). Every submission carries the run's replay recording + `board.EngineVersion`; without a shippable recording the UI shows `UNRECORDED` and refuses to submit (the server's `require_replay` trigger enforces the same). `mario -verify-pending` fetches pending rows via `Client.Pending` (PostgREST, service key) or, without a service key, via the direct-Postgres `board.DBClient` (`.env` `SUPABASE_DB_PASSWORD`; the postgres role bypasses RLS), replays each with `replay.Run` and settles each row by policy (2026-09-02, `20260902000000_hidden_scores.sql` applied live): replay reproduces claim+level → `SetVerified`; replay scores LESS than the claim (input lost en route to the live engine — SSH flow control, key-repeat inference) → **the replay is authoritative**, the row is corrected to the replayed score (`SetScore`) and verified; wrong level, replay failure, or version skew → `SetHidden` (new `scores.hidden` column, `board_rows` v4 filters `hidden = false` — row AND recording stay in the DB for forensics; the four 09-01 DELETEs that motivated this are unrecoverable). Nothing is ever DELETEd by the verifier. The ≥2-failure tripwire now counts HIDES only (a correction is determinism working; two hidden rows is the recorder-wipe class) — `TestVerifyPendingSystematicHideFails` is the contract, corrections stay green in bulk.
- **Platform split** by build tags: `cmd/mario/term_unix.go` (`!windows`), `cmd/mario/term_windows.go` (`windows`), `cmd/web/main.go` (`js`, the WASM entry).

## Code Conventions & Common Patterns

- **Stdlib only.** Adding a dependency needs strong justification; even the leaderboard client is plain `net/http` + `encoding/json`.
- **Determinism is load-bearing.** No `math/rand`, no `time.Now()` in engine or render logic; blink/pulse effects key off `g.Tick`.
- **Purity split**: `engine.Update` mutates state; `render.*` is a pure function of state (no I/O, no clocks). UI/network side effects live in `internal/ui` behind injectable funcs.
- **Error handling**: gameplay never fails on leaderboard errors — submit/fetch failures degrade to `OFFLINE` status strings; `maybeSubmit`-style flows swallow config errors and stay silent.
- **Arcade-string constraint** (world/HUD overlays only — the leaderboard screens are real text now): anything drawn through the 3×5 pixel font may use `A-Z 0-9 space . - + / : ! ?` only. Uppercase everything; no `_`, no lowercase; long lines ladder down via `pickTextPx(candidates, maxW)`.
- **Names**: max 8 chars, charset `A-Z 0-9 . -` — the single Go-side source of truth is `persist.NameCharSet` (consumed by ui name entry, `persist.SanitizeName` and `board.SanitizeDisplayName`, which protects the terminal/DOM from peer-stored legacy rows); a DB CHECK regex mirrors it in SQL.
- **Go 1.22 style**: `for i := range n` (project rule); errors wrapped with `%w`; table-driven tests.
- **Layout invariants**: title screen text positions come from `titleTextEls` (single source of truth); clouds must never paint a pixel inside a title text band (`cloudBlocked` does pixel-level suppression).
- **Persistence**: NONE on the user's machine — no config files, no input-calibration files (a deliberate privacy choice; the calibration API was removed with `keys.json`). Player identity is process-lifetime only (fresh UUID per native launch, cached so one run = one device id). The single allowed store is browser localStorage (`mario.player`, js build only).
- **Commit style**: short lowercase imperative subjects (`board: dark band covers header too`).

## Important Files

- `mario.go` — library facade: `Options`/`App` (`New`, `Feed`, `Step`, `Run`, `UI`, `Quit`, `StartDaily`, `Resize`); package doc shows the embed-as-easter-egg pattern. The viewport follows the terminal live: `Resize` (any goroutine) lands on the next `Step`, `render.Diff` clears + full-repaints on size change, the native runner hooks SIGWINCH (Windows: console-size poll), and `sshd.Session.OnResize` fires on mid-session window-change requests
- `demo.go` — `LoadLevels`, `RunDemo` (the deterministic demo script lives in `internal/ui/script.go` and doubles as the attract-mode input)
- `cmd/mario/main.go` — CLI entry, flag inventory (`-demo -demoticks -level -width -basic -scores -ui-preview -daily -verify-pending -dump-replays -replay -trace-window -day -serve -hostkey -mosh -mosh-ports -maxsessions -cheats -nobell`; `-cheats` or web `?cheats` sets `engine.Game.Cheats`: fireball cap lifted, run deliberately NOT recorded — the UI shows UNRECORDED and refuses to submit, so cheat runs can never reach the leaderboard; `-version` prints `render.Version` (nix-injected commit) + `board.EngineVersion` for deploy-skew checks; `-nobell` disables the terminal-bell sound feedback — by default `Options.Sound` feeds engine sound events to `cmd/mario/bell.go`, which emits throttled BEL bytes on the output stream for local, SSH and mosh alike), terminal lifecycle (raw mode, kitty push/pop, cleanup on signal), stdin pump
- `cmd/web/main.go` — WASM entry (`go build ./cmd/web` under GOOS=js)
- Repo hygiene: never commit `.env`; new worktrees need it copied in manually (leaderboard silently offline otherwise). For local dev, `chmod 0600 .env` since it holds the DB password.
- **Leaderboard rate limits** (`supabase/migrations/20260825000002_rate_limits.sql`, applied live): a BEFORE INSERT trigger caps anon submissions at 10/min per source address (from Cloudflare's `cf-connecting-ip` via the `request.headers` setting) and 2/min per device_id. Bursty probes or LIVE tests must pace themselves or they get `400 too many submissions`. The peer-filled `scores.ip` column is hidden from anon by column-scoped SELECT grants — `select=*` fails for anon by design.
- **Leaderboard hardening** (`20260825000003_pow_and_privacy.sql`): submissions require 20-bit SHA-256 proof-of-work over `<device_id>:<score>:<nonce>` (solver in `board/pow.go`, verifier in `verify_pow()` trigger — keep difficulty in sync); `device_id` is NOT readable by anon (mine-ness arrives precomputed via the `board_rows` RPC, so don't reach for `Row.DeviceID`); nightly pg_cron job keeps top-500 rows / drops >60d. Reads go through POST `/rest/v1/rpc/board_rows`, inserts must carry `pow_nonce`. Submissions also carry `level` (1-based level reached, clamped 1..99 client-side and by a DB CHECK; legacy rows read as 1) — `board_rows` returns it and every board surface renders it as an `L<n>` column (`20260826000000_level.sql`).
- **Daily mode** (`20260826000000_daily_mode.sql`, merged with the level column in `20260826000001_board_rows_union.sql`): scores carry `mode` ('classic'|'daily') and `day`; `board_rows(p_device_id, p_limit, p_mode, p_day)` — null/`classic` reads the classic board only, `'daily'`+day reads one challenge board. Enter via title `'d'` (terminal key or the web DAILY pad button) or `mario -daily`. The UI's default fetch branches to `TopMode` when the run was daily — keep that wired through `UI.dailyMode()`.
- **Play context** (`20260829000000_play_context.sql`, applied live): every score row also carries operator-only diagnostics — `surface` (`local`/`ssh`/`web`), `user_agent` (client-supplied on web, else defaulted from the request's User-Agent header by the `scores_user_agent` trigger), `term` (pty-req TERM via `sshd.Session.Term()`), `colorterm`, `input_regime` (`kitty`/`legacy` from `input.Mapper.SawKitty()`) and `viewport` (WxH at submit). They flow `Options.Surface/Term/…` → `ui.SetPlayContext` → `board.Entry` (clamped by `ClampPlayContext`, mirrored by DB CHECKs), are insert-granted but NOT select-granted to anon, and never leave through `board_rows`; `-verify-pending` prints them on each KEEP. Board fetches also retry once on error: a transient hang to the 15s timeout against the Supabase/Cloudflare edge (observed live on the SSH host) must not read as OFFLINE.
- **Play-session telemetry** (`20260830000000_plays.sql`, applied live): the SSH host writes ONE row per connection to the same Supabase service as the scoreboard, at disconnect (`board.PlaySession` via `Client.RecordPlay`, fire-and-forget goroutine in `playSession`): ip (player's SSH origin), started/ended timestamps, deepest level, best score, runs started (`App.Runs()` — the recording-arming rule), submitted (`App.Submitted()` — a score row actually landed), term, `colorterm` (the DECIDED depth signal via `Session.ColorTerm()` = env > TERM family > DA probe — NOT the raw env request), `colors` (24, 256 or 16 — the palette actually rendered; 256 = the fixed xterm cube tier), `client` (the SSH identification string via `Session.ClientVersion()`, the ssh-surface user agent), input_regime, viewport, engine_version. The `plays` table is WRITE-ONLY: anon has insert but no select grant and no select policy (RLS denies reads twice) — analytics are direct-DB/operator only, the game never reads back. Server-originated rows only (player machines never phone home; local/web play stays invisible unless the player submits). Anti-abuse mirrors the scores hardening (per-ip 30/min + global 120/min BEFORE INSERT trigger, nightly `plays_retention` prunes >365d). A `Session.Logf` belt-and-braces line (`play ip=… runs=… level=…`) goes to the server's stderr/journald regardless of Supabase availability.
- `cmd/web/main.go` — browser entry; page contract: page provides `marioFrame(w,h,rgb)`, `marioBoard(json)` (leaderboard DOM text), optional `marioSfx(name)` (WebAudio synth; called once per engine sound event) and `marioTitle(bool)` (title-screen enter/exit; the page shows the DAILY pad button only there) before load; game exports `marioFeed(keys)`, `marioSize(worldPxW, worldPxH)`
- **SSH game server** (`mario -serve ADDR`, `internal/sshd/`): unauthenticated (`none` auth, any username) but the ONLY service is the game — the one exec exception is the mosh handshake (`-mosh PATH`: `mosh-server new …` argv is shell-quote-parsed against a strict whitelist, rebuilt with our own binary/port-range — the client's command is NEVER exec'd); the game env under mosh comes from `moshEnv`: mosh-server 1.4.0 unconditionally overwrites the child TERM to `xterm-256color` (client TERM never survives mosh), so the env strips inherited TERM/COLORTERM/LC_* and sets `COLORTERM=truecolor` when the ssh-phase pty TERM is a truecolor terminal (`render.TrueColorTerm`, shared with `trueColorSupported`) or the client forwarded COLORTERM as an env request (`ssh -o SendEnv=COLORTERM` — the fix for VTE/gnome-terminal, which only hint via COLORTERM and lose it through mosh); without that signal the game ran its ANSI-16 palette over mosh — the 'less colours' bug — while mosh 1.4's cell model passes 24-bit color fine; since the DA-probe landed the same `channel.decideColorTerm` also feeds plain-ssh sessions (`Session.TrueColor`): when a shell session starts (pty present) the server asks the client terminal to identify itself (DA2 `CSI > c` + DA3 `CSI = c`, vim's termresponse trick — the only way to tell VTE from Apple Terminal, which both speak `xterm-256color` but only one renders `38;2`), sniffs the reply out of the inbound stream (`internal/sshd/termprobe.go`; keystrokes typed meanwhile are buffered and replayed by `OnFeed`, late replies are filtered so they never reach the game as input) and maps the family (`daDecision`: VTE/tmux/Konsole/xterm≥362/kitty/wezterm/ghosty/contour/foot/iTerm2 truecolor — iTerm2 hex-encodes its DA3 name as `6954726D` = "iTrm" — Apple_Terminal not). Shell sessions only — mosh.pl runs its ssh with `-n` (stdin /dev/null) and mosh-server eats unknown outbound CSI, so a DA reply can never cross a mosh handshake: gnome-terminal-over-mosh without `SendEnv COLORTERM` can never get 24-bit — it now falls to the fixed 256-color cube instead of base-16 (TERM=xterm-256color guarantees the cube; the cube+gray indices are spec-exact, unlike the profile-dependent base colors that caused washed-out reds). Precedence: forwarded COLORTERM env request > TERM family > probe; silent terminals wait at most `Server.ProbeWait` (250ms default) once per connect, pre-title. (The probe also exposed a latent race in `TestServeQueueHandoverE2E` — shells race across connection goroutines, so the test now admits player 1 before spawning player 2.); subsystems and every global request except `keepalive@openssh.com` are refused, one session channel per connection. `-serve` rejects play-only flags it would silently ignore (`-daily`, `-width`, `-demo`, `-cheats`). Sessions are capped at `-maxsessions` (default 16, measured: the mario-vps single core holds full-quality play to ~16-20 concurrent sessions, saturates ~32 — see `cmd/mario/serve_load_test.go`, the `LOAD=1` harness); over-capacity players join a FIFO queue (`internal/sshd/admission.go`, default depth 32, 10-min timeout) showing position + a Little's-law ETA from a session-length EWMA, admitted strictly in order via slot transfer under one mutex (mosh servers separately capped by a HARD CAS limit — `Server.MoshMax`, default 16, via `sshd.RunningMosh`; over-cap mosh requests get a real CHANNEL_FAILURE). mosh-server runs in its own process group and must OUTLIVE the SSH connection — the channel tears down when the handshake parent exits (mosh.pl's `waitpid` hangs forever otherwise; sshd semantics), after a 100ms drain grace for the in-flight CONNECT line; the client-side `-s` means bind-to-ssh-source-IP in nix mosh 1.4 and is deliberately NOT forwarded (mosh-server would bind one interface while the client dials another). Each connection gets its own `App` plus a `persist.Session` identity (`Options.Session`) — hosts running many Apps in one process MUST pass a Session: the process-wide `persist.LoadPlayer` cache is not per-player (it IS mutex-guarded since 2026-08-30 — the submit goroutine's SaveName races the tick goroutine's read), and a shared device id would trip the 2/min per-device rate limit collectively. Protocol notes that cost an afternoon: (1) modern OpenSSH does NOT reset packet sequence numbers at NEWKEYS unless strict-kex is negotiated (we don't offer it) — the per-direction counter runs for the connection's life (`serverKex` carries `seq` across the key swap); (2) CHANNEL_SUCCESS/FAILURE replies carry the 4-byte recipient channel; (3) teardown order is exit-status → EOF → CHANNEL_CLOSE → 300ms grace → TCP close (closing with writes in flight RSTs); (4) client CHANNEL_EOF means stdin-done, not session-over — keep rendering (attract mode) until CHANNEL_CLOSE/DISCONNECT. Input feel is three more invariants: (1) the conn reader goroutine NEVER writes to the socket once frames may flow — keystroke bytes feed the game first, before any protocol bookkeeping, and everything the protocol must send back (window adjusts, keepalive/request replies, and the channel teardown burst — exit-status/EOF/CLOSE) rides a per-connection control pump (the control lane, `control.go`: `pumpControl`, `writeControl`/`syncControl`): a synchronous reader write behind a frame chunk wedged on a full kernel send buffer stalls input delivery for up to `writeTimeoutSec` (~30s measured; regression `TestKeystrokeFedWhileOutputCongested`), and accepted conns set TCP_NODELAY so control packets don't queue on Nagle behind 256KB frame chunks; (2) receive-window adjusts coalesce into a lossless owed counter replenished at half the 2MB window (`adjustFloor`, OpenSSH's adjust-at-half policy — human typing generates zero adjust packets, and a sub-floor residue legitimately stays owed, carrying toward the next crossing; regression `TestInputWindowReplenished`), and the bell rides a fire-and-forget sink in `playSession` because BEL writes happen on the tick goroutine (a closed channel window must never stall the simulation); (3) `playSession` renders on the tick goroutine (`Stream.Snapshot`) but diffs/writes on a writer goroutine (`Stream.Flush`, latest-frame mailbox) so SSH flow-control backpressure drops a frame instead of dropping ticks — the 60 Hz simulation and input polling never stall on a slow link (loopback keypress→output measures ~18ms = one tick; the rest of remote latency is network RTT). Real-client E2E: `SSHE2E=1 go test -run TestServeSSHClientE2E -v ./cmd/mario` plus the latency guard `TestServeSSHClientLatencyE2E` (gated like LIVE; the in-package client cannot catch interop slips), `TestServeQueueHandoverE2E` for the queue handover, and `LOAD=1 LOAD_N=…` for capacity sweeps. Input-calibration warm-start: `playSession` builds its mapper via `sessionMapper` (`calCache`, keyed by `Session.RemoteAddr()` host part, in-memory, capped 128, idle sessions never clobber) so a repeat player's reconnect starts with the measured OS repeat delay and hold habits instead of paying the cold-mapper first-hold stutter (~0.5s per movement key) at every connect — server RAM only, the no-persistence privacy rule (which is about the player's machine) is untouched.
- `internal/ui/ui.go` — leaderboard state machine; ask keys: `Y` submit, `N`/`Q`/`ESC` decline, `R` decline+restart (same edge as the board's `r`); entry keys: `ENTER` accept, `BS` delete, `ESC` back; board keys: `L`/`Q` close; title `l` opens; title `i` opens the about screen (`UIAbout`, close on `I`/`Q`/`ESC`). The submit ask is once per RUN, not per session: every run start (`App.Step`'s card-arming branch) calls `leaderboard.ResetForNewRun()` — a decline followed by a mapped-`r` restart used to leave `asked` set forever, silencing the prompt for the whole session (regression: `TestDeclineThenBannerRestartRearmsAsk`).
- `internal/persist/` — process-lifetime player identity (no disk on native, localStorage on js) + name sanitisation

## Gotchas

- **Wire-encoding contract (bandwidth is a feature)**: SGR styles were 80% of frame bytes; `render.String`/`Diff` share `sgrState`, a minimal-diff SGR encoder (state persists across cells/runs/rows; a space never carries fg; attribute *clears* fall back to a full `0;…` form — `ansi2png.py` and `diff_roundtrip_test.go`'s terminal model must both parse whatever you emit). Solid pixel pairs (upper==lower) are `' '` over the colour, not `▀`. `Diff` bridges ≤12-cell clean gaps by re-writing identical cells when the exact serialized cost (styles included) beats a cursor address, and advances continuation rows with `\r\n`. Tripwires: `TestDiffStreamRoundTrip` (byte-stream → screen reconstruction) and `TestStreamBandwidth` (B/tick caps). Keep `tools/shots/ansi2png.py` able to consume real output — it now parses CUP row/col, CUF and private modes; its CUF handler once shadowed the loop bound `n`.

- **Worktree policy (this machine)**: agent work happens in linked worktrees (`git worktree add .worktrees/<feature> -b <branch>`, or sibling `../game-<feature>`), never in the direct checkout; copy `.env` in; merge back into `main` (expect divergence — the user commits concurrently) and re-run the full suite on merged `main` before pushing. **Hook-enforced since 2026-08-25**: `.omp/hooks/pre/worktree-guard.ts` blocks `edit`/`write` calls targeting the main checkout in every omp session here (`.worktrees/**` and sibling worktrees pass; `bash` — git merge/push — is untouched; the guard fails open on unusual shapes, so it is a guardrail, not a jail).
- **Branch hygiene (2026-08-27, user rule)**: worktree branches stay LOCAL — merge into `main`, push ONLY `main`, then delete the branch. Never `git push origin <feature-branch>`: stale remote feature branches accumulated that way (six were purged with the history rewrite). The remote carries `main` + tags, nothing else.
- **Distro packaging**: `make deb` / `make rpm` + `packaging/aur` + `flake.nix` are versioned off `git describe`/the release tag — no `EngineVersion` bump for packaging-only changes. The flake uses `buildGoModule` (CGO off comes from its env defaults — don't shadow `CGO_ENABLED` with a derivation attr; it errors). AUR is local-build only — never wire a publish job or an `AUR_SSH_KEY` secret back in.
- **Android APK**: The APK is a thin WebView shell around the WASM build, locked to `sensorLandscape` (portrait squashes a side-scroller) and loaded with `?touch` so the on-screen pad always shows — pointer media queries misjudge some devices (a Samsung test phone reports `any-pointer: fine`, hiding the pad in Chrome too; the site's fallback is the 🎛 bar toggle — a page-level fix may be worth it). Because Chromium blocks `fetch()` on `file://` origins, `MainActivity` intercepts requests to `https://appassets.androidplatform.net/assets/*` and serves `dist/web` from the APK assets. The `packaging/android/mario.keystore` is committed and self-signed (zero value, for sideload convenience only); if distributing via the Play Store, replace it and use real GitHub Actions secrets. Rotated 2026-08-27 and the pre-rotation keystore purged from ALL git history (git-filter-repo) ahead of going public — anyone holding an install signed by the old key must uninstall before updating. `adb install -d` (or uninstall first) is needed for dev builds: their date-fallback versionCode is below any tagged release's.
- **APK CI vs runner speed**: the composed Android SDK's first materialisation on the runner is pathologically slow (auto-patchelf builds i686 `ncurses` for the 32-bit legacy SDK binaries; observed 38min+ without finishing). If the apk job times out after a nixpkgs bump, import the closure from a dev host instead of letting the runner build it: `nix build .#devShells.x86_64-linux.android --out-link /tmp/shell && nix-store --export $(nix path-info -r /tmp/shell) | ssh root@trucker 'incus exec github-runner-mario -- nix-store --import'` (same flake.lock → identical hashes; the runner then substitutes locally and the job takes ~2min). The runner's nix now also accepts `i686-linux` (`extra-platforms`, set in ~/nixos-incus github-runner-mario.nix) — required for this SDK at all.
- **iOS IPA (Linux-built)**: `make ipa` compiles `packaging/ios/main.m` (ObjC WKWebView shell) with `clang -target arm64-apple-ios` + `lld` + `ldid` — no Mac, no Xcode. The ipa CI job is best-effort like the APK (`continue-on-error`, never gates release/Pages).
- **omp-generated release notes**: every tag release's notes are generated by `omp -p` from the previous-tag..tag commit log (release.yml `notes` job) and land in exactly two places: the release **body** (curt intro + compare link, via `gh release edit --notes-file`, replacing the release job's `--generate-notes` placeholder) and `CHANGELOG.md` on `main` as a `## <TAG> — <date>` section (best-effort push from the job, one rebase retry). It is best-effort (`continue-on-error`) because pages.yml gates on the release workflow's overall success — a model hiccup must never block the Pages deploy. Two cross-repo prerequisites: `omp` in the runner image (nixos-incus `github-runner-mario.nix` extraPackages, bun2nix-built from the `oh-my-pi` flake input) and the `ZHIPU_API_KEY` repo secret (flat-rate GLM coding-plan key; model `zhipu-coding-plan/glm-5.2`, thinking off). Bumping the `oh-my-pi` input in nixos-incus + in-place re-activation updates the runner's omp.
- **Check `git status` before `git add -A` on the main checkout** — the user keeps WIP test files there; sweeping them up has shipped half-done tests before.
- Ranged edits in this repo have repeatedly misfired (especially after `gofmt` renumbering); prefer read-then-full-file writes for multi-line changes, and single-line 1:1 replacements otherwise.
- **UI trigger keys must be mapper no-ops**: any byte the input mapper doesn't know maps to `AnyKey`, which starts the game on the title screen before `scoreUI` can see it. `'l'` (leaderboard) is deliberately mapped to a no-op event in `mappedKey` — a new UI hotkey needs the same treatment (regression: `input.TestLeaderKeyIsNotAGameKey`). `'d'` (daily) CANNOT be a no-op (it is WASD-Right), so its title trigger is checked in `Router.TakeDailyAtTitle` BEFORE the engine update consumes the same press as Right — keep that ordering.
- **Plant markers are float-adjacent**: `Builder.Plant` stores `{x+0.65, topRow}` and `Builder.Rows` recomputes the marker column with `math.Round(p.X-0.65)` — a plain `int()` truncates `15.999…` and shifts the marker one column off its pipe (regression: `TestDailyLevelsSolvableShape`).
- **Bump `board.EngineVersion` on ANY gameplay/level change** (engine, levels, daily generator): the verifier rejects every pending row whose recording predates the current build — that is the safety direction, but forgetting to bump means live submissions get deleted at the next verification pass.
- **`WEBLDFLAGS` in the Makefile is load-bearing for the web board**: the wasm has no environment, so `board.DefaultURL`/`DefaultKey` exist only via its `-X` injection. The hardening rework (a7e7a5f) deleted the definition while keeping the reference — make expands undefined vars to empty, so every web build silently shipped with an `OFFLINE` leaderboard (Pages, mario.baby, APK) until 09602eb restored it. `make web`'s credential guard validates the vars but cannot catch a dropped ldflags line; `make web` now greps the built wasm for `supabase.co` post-build and fails loudly, so the a7e7a5f class is tripped at build time.
- **Recording alignment is load-bearing**: `replay.Run` must start from exactly the state `App.Step` records from (first world-card tick; `Reset()`/`BeginDaily()` equivalence). If run-start flow ever changes (new states, a skip-intro path), update `Recorder` arming in `mario.go` and `replay.Run` together — the run-vs-live equality tests in `replay/replay_test.go` are the tripwire. **The arming check runs on the card's FIRST tick only and compares `a.prevState`, which must be assigned BEFORE `g.Update`** (the Dying→Card transition happens inside Update): the original post-Update assignment meant every card tick saw `prevState == StateWorldCard`, the Dying/ScoreTick continuation case was dead code, and every death respawn re-armed the recorder — the submission then carried only the final life's segment and the verifier deleted it (live 2026-08-30: every death-containing SSH run was silently dropped; caught via a scripted pty playthrough whose 400-point run replayed to 0). Regression: `TestRecorderSurvivesDeaths` (recording spans deaths AND replay-equals the live run).
- **Checkpoint respawns must never be lethal at tick 0**: a level reload resets every enemy to its spawn point, so a spawn overlapping the checkpoint column killed the player one tick after the world card and drained all remaining lives in a loop (live 2026-08-30: 1-1's guard goomba sat exactly on the auto-picked column; found by tracing the submitted recording). Guarded twice: `computeCheckpoint` skips columns near enemy/plant spawns and inside fire-bar discs (`Level.spawnThreatNear`), and `respawn`/`loadLevel` call `clearSpawnThreats` — the invariant for generated/hand-authored levels that bypass the picker. Regressions: `TestRespawnNotLethalAtCheckpoint`, `TestCheckpointAvoidsSpawnThreats`. Postmortem tooling: `mario -dump-replays N` (DBClient.Latest → replay-<id>.json + metadata) and `mario -replay FILE` (`replay.Trace`: tick-by-tick transitions + a death-cause dump). When a row's claimed score disagrees with its recording's replay, check `engine_version` on the dump line FIRST — cross-version recordings diverge by design and the verifier drops them as `version` (2026-08-30: an SSH run recorded on pre-merge main 72b5eab scored 3300 live and replays exactly 3300 under that commit, but 1500 under 30b — pure skew, not a determinism bug). To truly validate a mismatched row, `git worktree add` the era commit (the version string covers whole main windows, not single builds) and replay.Run there before suspecting the recorder.
- **Terminal-mode ORDER is load-bearing** (native `run()` and `playSession` alike; kitty spec Quickstart): the kitty-keyboard stack is **screen-scoped** — push AFTER the alt-screen enter (`?1049h`), pop BEFORE the alt-screen exit (`?1049l`), both on the alt screen. The old prologue pushed on the *main* screen's stack, so the epilogue's pop (on the alt screen's empty stack) was a no-op and the pushed level survived the session — the player's shell was left emitting CSI-u garbage (live report 2026-08-29: `07;129u…:3u` after `ssh mario.baby`). Popping after `?1049l` instead would target the main screen's stack and could eat a level the shell pushed there (zsh kitty integrations do) — don't "fix" it that way either. Tripwire: `TestServeSSHClientE2E` asserts `?1049h` precedes `>11u` and `<u` precedes `?1049l`.
- **Typeless kitty presses are still kitty** (`input.drain`): ghostty and kitty omit `:1` on press events (it's the default event type), so `CSI 100;129u` arrives with `evType==0` and used to fall into OS-repeat inference — first-hold stutter plus grace overrun on taps, i.e. "lag and run-on" over SSH. A CSI-`u` final is unambiguous kitty (legacy terminals never send one); once any is seen the regime latches and typeless CSI arrows normalize to presses too. Legacy-only streams keep the inference model (`TestLegacyArrowsStayLegacy`).
- **The router owns keyboard handoff, including holds** (`internal/ui/router.go`): while a leaderboard screen captures, bytes go to the UI alone — so the mapper never sees releases for keys held at capture time. Entering capture (and the board's 'r' restart edge) calls `Mapper.ReleaseAll()`, or the leaked hold runs the next game on (a sticky kitty hold survives forever). Regression: `TestRouterClearsHoldsOnCapture`, `TestRouterReleaseAllOnRestart`.
- **`LoadLevels("")` returns nil on purpose** — nil is `mario.New`'s "use the built-ins" signal AND what keeps runs replay-trusted (`levelsTrust = len(opts.Levels)==0`); returning the built-ins explicitly made every native/SSH run show UNRECORDED and unsubmitable (live report 2026-08-29). Custom `-level` files must keep arriving as an explicit slice.
- **BEL bytes over SSH ride the writer goroutine** (`playSession`): the bell ringer writes through a non-blocking channel drained after each frame flush — a BEL written from the tick goroutine could block on SSH flow control and stall the 60 Hz simulation (mushy controls, late releases). Bells drop when the writer is busy; that is the correct trade.
- The pixel font's missing glyphs are a *product constraint*: `[`, `_`, lowercase etc. render wrong — the name-entry field draws its own rails instead of brackets for exactly this reason.
- `engine.Input` is a fixed bool struct; anything needing character keys (name entry) must bypass the mapper via the Router's capture routing. `'k'` is the suicide key (edge-triggered `Input.Suicide`, `spKill` in the mapper, replay mask bit 9): a mapped game key, so unlike unmapped bytes it can never start a run from the title — don't repurpose it as a UI trigger without the `'l'` no-op treatment.
- **UI input capture vs escape sequences**: The UI consumes single bytes for typing/control. `input.PlainDecoder` strips out non-text escape sequences (preventing lone `0x1b` from instantly closing the UI) and translates `CSI u` text keys back into normal bytes.
 - **Single-key-repeat demotion (legacy regime)**: Wayland compositors (and anything behind tmux, which strips the kitty negotiation) autorepeat only the newest pressed key — holding right and pressing jump silences right's repeat stream forever. The mapper's demotion model (`input/input.go`: `demotedHeld`, resurrection, `upExtendTicks` cap for jump) exists to keep proven holds alive through that; don't "simplify" those arrays away. Regression tests: `input/demote_test.go`.
- Viewport extremes are real: `ViewH` can be 4 tiles tall; every new screen must survive the size sweeps or `TestScoreUIAllViewportSizes` fails.
- The WASM build shares `play()` but not `render.Stream` — it rasterizes via `RenderPixels`; changes to overlay drawing must work through both `worldFrame` paths. HUD/status line content comes from ONE shared builder (`hudSegs`/`hudLadder`/`statusLadder` in `render/hud.go`; the old 1.6k-line render.go is now split same-package into palette/screen/camera/world/hud/title.go) consumed by both the terminal-font and px-raster paths — `TestHudStatusContentParity` is the tripwire; never hand-duplicate a HUD string on one surface only.
- **Render buffers recycle** (`render`): a `Stream` owns a small screen pool plus its world raster, and per-tick pixel callers (web/EFI) reuse their composite frame and RGB buffer via `RenderPixelsInto`/`RGBBytesInto`. A `Screen` returned by `Snapshot` is transient — it is recycled two flushes later (it must first serve one flush as the diff baseline), so never retain it across ticks; copy if needed.
